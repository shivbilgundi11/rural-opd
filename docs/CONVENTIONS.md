# Conventions

Decisions made in Module 1. Later modules **apply** these; they do not
relitigate them. If one genuinely has to change, change it here first and note
which modules need reworking.

---

## 1. Money

**All monetary values are integer paise.** `3000` is INR 30.00.

- No floats anywhere in the money path. No decimal strings. No rupee columns.
- The only conversion is `rupeesToPaise`, and it happens exactly once, at the
  edge where a human types a fee into the staff admin UI (Module 5).
- `Paise` is a branded type in `@rural-opd/shared`. A raw `number` cannot be
  passed where paise is expected without going through a validating
  constructor.
- Amount comparison is exact equality via `amountsMatch`, never a tolerance.

**Why it is a type and not a convention.** PRD §6 requires the amount on the
appointment, the payment order and the gateway webhook to match before a token
is issued. A one-paise float rounding difference there is not a display bug, it
is a patient who paid and did not get a token. `parseFloat` is banned by ESLint
across the repo.

## 2. Time

- Every timestamp column is `timestamptz`, stored in UTC.
- Rendering happens in hospital-local time, and the hospital's timezone is a
  column on `hospitals` — not an app-wide constant. A patient travelling does
  not change which queue they are in.
- Dates that identify a _session_ (an OPD day) are `date`, not `timestamptz`.
  "The morning session on 2026-08-20" is a calendar fact, not an instant.
- Durations and intervals are stored as integer minutes, not `interval`.

## 3. Identifiers

- `uuid` v4, generated by the database (`gen_random_uuid()`), for every entity
  a client can reference.
- **Except** `queue_events` and `audit_log`, which use `bigserial`. Both are
  append-only and scanned in order; a monotonic integer key makes those scans
  cheap and gives events a natural total ordering.
- Clients never generate ids. An id that exists only on a device is an id that
  survives a failed request.

## 4. Naming

| Thing                         | Convention                  | Example                                   |
| ----------------------------- | --------------------------- | ----------------------------------------- |
| Database table, column        | `snake_case`, tables plural | `opd_sessions.session_date`               |
| Database enum value           | `SCREAMING_SNAKE`           | `PENDING_PAYMENT`                         |
| TypeScript variable, function | `camelCase`                 | `issueToken`                              |
| TypeScript type, interface    | `PascalCase`                | `AppointmentSummary`                      |
| React component               | `PascalCase`                | `TokenHeroCard`                           |
| Component file                | `PascalCase.tsx`            | `TokenHeroCard.tsx`                       |
| Any other file                | `kebab-case.ts`             | `use-queue-subscription.ts`               |
| Edge Function directory       | `kebab-case`                | `supabase/functions/create-payment-order` |
| Environment variable          | `SCREAMING_SNAKE`           | `EXPO_PUBLIC_SUPABASE_URL`                |

Enum values mirror PRD §5 exactly. `StatusBadge` maps 1:1 from them, so an
enum value the PRD does not list is a specification change, not a code change.

## 5. Types

- **Database types are generated.** `packages/shared/src/db.types.ts` comes from
  `pnpm db:types` and is the only source of table rows and enums. Nothing
  re-declares an enum by hand.
- An ESLint rule bans hardcoded status string literals outside
  `packages/shared`. A client that can type `"CONFIRMED"` is a client that can
  invent `"CONFIRMED_PENDING"`.
- `strict`, `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes` are all
  on. `noUncheckedIndexedAccess` in particular means `queue[0]` is
  `T | undefined` — which is correct, because an OPD session with nobody in it
  is a normal Tuesday, and Modules 11–12 index queue arrays constantly.

## 6. Errors

- One closed union, `ErrorCode`, in `@rural-opd/shared`. Edge Functions, RPCs
  and both clients speak the same `AppError` shape.
- A client can exhaustively `switch` on it, and the compiler flags the switch
  when a later module adds a code.
- `message` is patient-safe copy. `details` is for developers and carries no
  medical or payment identifiers.

## 7. Logging and privacy (PRD §8)

- Never log: patient name, phone, age, symptoms, any medical field, full
  payment identifiers, or an OTP.
- Log instead: appointment id, correlation id, error code, and non-identifying
  counters.
- `no-console` is a lint warning; `console.warn` and `console.error` are
  allowed. Structured logging arrives with Sentry in Module 15.

## 8. Line endings

LF everywhere, enforced by `.gitattributes`. Windows is the primary development
machine and CRLF in `.sql`, `.sh` and Deno files produces parse errors from the
Supabase CLI that look like unrelated syntax bugs. After changing
`.gitattributes`, run `git add --renormalize .`.

## 9. Commits

Conventional Commits, with the module number as the scope:

```
feat(m02): add appointments table with expiry constraint
fix(m10): reject webhook when order amount differs from appointment
chore(repo): bump pnpm to 9.15.9
```

`commitlint` enforces the scope list (`m01`–`m15`, plus `repo`, `ci`, `docs`,
`deps`). The scope is not decoration: it is how a reviewer knows which module's
acceptance criteria a change is answerable to.

## 10. Repository shape

- **One backend.** TA §1. There is no `apps/api` and there will not be one. If
  something feels like it needs a Node server, it is an Edge Function.
- `packages/shared` is regenerated on every migration. `packages/tokens` changes
  only when `DESIGN.md` does. They stay separate so a schema change does not
  invalidate the design-system build cache.
- `packages/shared` ships TypeScript source, not `dist`, because Metro needs to
  transpile it. If that ever changes, keep the `react-native` export condition
  pointing at source.
